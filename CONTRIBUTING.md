# Contributing to Cinderbelt

Thanks for your interest. Read [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) first; it explains how
the code is organised.

## Setup

You need Node.js (a current LTS) and npm.

```text
npm install
npm run dev        # http://localhost:5317
```

Python and Blender are only needed if you regenerate art or music (see below).

## Project rules

- **English code.** Identifiers and code comments are English. `npm run lint:lang` enforces this
  for comments and test titles.
- **Bilingual game.** The game ships in Slovak and English. Every player-facing string lives in
  `src/i18n/`, in both languages, never hard-coded in a component or in the simulation. Add a
  string to both the `sk*.ts` and the `en*.ts` module; the parity test fails otherwise. Only the
  active language is loaded at runtime, so `setLocale()` is async on the first switch: await or
  poll in e2e tests.
- **Pure simulation.** `src/sim` must stay deterministic: no three.js, no DOM, no `Math.random`,
  no `Date`. Rendering and UI only read simulation state. Query results are often cached and shared,
  so treat them as read-only, and do not nest uses of the same scratch list
  (`src/sim/scratch.ts`).
- **Saves are versioned.** Any new persistent state needs a version bump in `src/sim/save`, a
  migration and tests. The save/load determinism tests must stay green.
- **Hull language UI.** UI follows the design system in `src/ui/theme`. No generic dark-glass
  panels.
- **Performance budget.** See the end of [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). After a
  change that can cost frames, run `npm run test:perf`.
- Write tests first for logic. For UI and rendering changes, take Playwright screenshots and
  look at them.

## Checks before a pull request

```text
npm run typecheck
npm test
npm run lint:lang
npm run build
npm run test:bot
E2E_PORT=5327 npx playwright test tests/e2e/<spec>.spec.ts --workers=2 --output=test-results-mine
```

Run only the e2e specs your change touches; the full suite is slow. `E2E_PORT` starts a separate
dev server so you do not clash with one that is already running on 5317. Do not run long bot or
saboteur runs (many seeds times many hours) unless your change really affects the economy; then a
short sanity run (up to 5 seeds, 1 hour) is enough.

## Fixtures

To test a point deep in the game without playing there, start from a saved position:

- in the browser: `http://localhost:5317/?fixture=hour1` (dev server only);
- in a Playwright spec: `loadFixture(page, 'hour1')` from `tests/e2e/fixtures.ts`.

The list of fixtures and how to regenerate them (`npm run fixtures`) is in
[tests/fixtures/saves/README.md](tests/fixtures/saves/README.md). Regenerate them when the save
format changes.

## Art and music

- **Art** is generated by Python scripts run in headless Blender. The Blender executable path is
  yours to configure; follow [art/README.md](art/README.md) for the exact commands and substitute
  the executable installed on your machine. Every build ends with `npm run assets:optimize`;
  `npm run assets:check` lists unoptimized files.
- **Music** is composed and rendered by `tools/music/build.py` (Python plus `ffmpeg` with libopus).
  See [tools/music/README.md](tools/music/README.md).

Please do not commit hand-edited binary assets that the scripts would overwrite; change the script
instead.

## Commits and pull requests

- Short, imperative subject line, optionally prefixed with the area, for example
  `sim: English comments`, `Audio: English comments and dev lab labels`, `Fix dock approach
  overshoot`. One logical change per commit.
- Stage files explicitly (`git add <paths>`) rather than adding the whole tree.
- In the pull request, say what changed and why, and which checks you ran.

## AI-assisted development

The project is developed largely with AI coding agents, and AI-assisted contributions are welcome.
They are held to exactly the same standard: the checks above must pass, the rules above apply, and
you are responsible for understanding and reviewing what you submit.
